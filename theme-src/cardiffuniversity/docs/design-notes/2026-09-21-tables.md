# Tables

Implemented 21 September 2026. Part of the second item under "Remaining theme migration" in the
[follow-up checklist](../plans/2026-09-21-follow-up.md), and a partial answer to the wide-table
part of the Phase 1 validation item (review Minor 9).

## Problem

Measured against the theme's own tokens:

- **Wide tables stretch the page.** Review Minor 9 said this was a risk; it is now reproduced. A
  14-column table with `nowrap` cells is 2,864px wide and makes the page 3,211px wide against a
  1,265px viewport. The theme had removed the section's scroll container so that focus rings
  would not be clipped, and nothing replaced it.
- **`.table-striped` painted odd rows Forest Green** (`#07873E`) with ink text, because the rule
  used `--color-accent-green`, which was plainly meant as a tint. That is 4.05:1, under 4.5:1.
- **Captions were grey-60**, which is 3.95:1 on white.
- **Tables were rounded (3px)** and declared `--shadow-sm`. That token is `none` today, so no
  shadow showed, but changing the shared shadow role would have put one on every table.
  The design system wants square structural panels and shadows only on overlays.
- **The lists-and-tables demo said tables "are responsive and will scroll horizontally on small
  screens if needed."** That was false.

## Decisions

Made by Nan on 21 September 2026.

| Question | Decision |
| --- | --- |
| How should a wide table avoid stretching the page? | An **opt-in wrapper class**, `.cu-table-scroll`. Nothing changes automatically. |
| Striped rows | A quiet grey-10 tint, ink text. |
| Corners, shadow, caption | Square, no shadow, grey-70 caption. |

The other options were a script wrapper (recommended, because it would also protect tables
authors forget to wrap) and CSS-only `display: block; overflow-x: auto` on every table. The
CSS-only route was measured and rejected: the page stopped overflowing, but a 3-column table in
an 870px container then had its cells cover only 370px while its border stayed 870px wide.

## What changed

- **Wrapper** (`_base-elements.scss`). `.cu-table-scroll` sets `overflow-x: auto`. A scrolling
  region has to be reachable by keyboard, so it also carries the theme's focus ring. The author
  adds `tabindex="0"`, `role="region"` and an `aria-label` naming the table; the theme cannot add
  or check those. A narrow table inside the wrapper still fills it.
- **Striped rows** (`_bootstrap-components.scss`). Odd rows are grey-10, at 16.73:1 with ink.
- **Tables** (`_base-elements.scss`). Square, `box-shadow: none`, and a grey-70 caption (5.74:1).
- **Demo** (`demos/lists-tables.html`). New "Striped Rows" and "Wide Tables" blocks, and the false
  scrolling claim in the accessibility note is corrected.

## Verification

- 166 automated checks pass (156 before), including 10 new `tables` checks. 8 of them failed
  against the old CSS for the right reasons; 2 guard behaviour that was already right (an even
  striped row has no fill, and a narrow table still fills its wrapper, which would fail under the
  rejected `display: block` approach). The shadow check changes the shared shadow role and
  expects no shadow, so it catches the token-change case described above.
- The generated reference is in sync and no theme class is undocumented.
- The two demo blocks were rendered in headless Chrome and reviewed by eye: the striped table
  shows the grey tint, and the wide table scrolls inside its wrapper instead of stretching the
  page.

Not verified: the real Xerte player, or a real project's tables.

## Deferred, explicitly

- **A wide table that an author does not wrap still stretches the page.** Automatic containment
  was offered and declined. If it is wanted later, the script wrapper is the option to build.
- **Nothing checks that authors add `tabindex`, `role` and `aria-label`.** Without `tabindex`, a
  keyboard user may not be able to scroll the wrapper in every browser.
- **Not reviewed:** the header style (uppercase, letter-spaced, a 2px rule), the row hover
  highlight, Bootstrap's other table variants (`.table-bordered`, `.table-hover`, `.table-condensed`)
  and the base template's own table rules.
