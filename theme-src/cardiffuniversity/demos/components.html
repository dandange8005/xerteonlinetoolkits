The components cardiffuniversity adds for Cardiff resources. Alerts, badges, progress bars, breadcrumbs, tabs and accordions come from Bootstrap and are on the Bootstrap page.

Callouts

Seven callout types — design system fa-stack markup

The markup used by the design system's own prototypes. Still supported, so prototype callouts paste in unchanged. For new Xerte content prefer the short markup below.

Information

Extra context.

Tip

A recommendation.

Good practice

The preferred approach.

Important

Something requiring attention.

Warning

A risk or problem.

Example

A worked example.

Key point

The main takeaway (default when no type class is given).

.cu-callout | -info | -tip | -good | -important | -warning | -example | -key (or no type class at all)
Seven callout types — short markup (preferred)

Same seven types and the same result, three elements instead of five. The theme draws the disc and glyph in CSS, so there is less to paste into the Xerte editor and no empty tags for the editor to strip.

Page chrome

Footer

An ink footer with no red. The player builds it from the project's customFooter HTML and puts it in #customFooter, so write only the columns: the theme lays them side by side and stacks them when the space is narrow. Set footerPos to replace the default footer. In that mode the player also appends its accessibility link, which the theme puts on its own row. For a logo, use an official white (reversed) version; the design system says never to recolour it.

Feedback tab and glossary

Neither is shown here: the feedback tab is fixed to the edge of the window, and the player places a glossary definition at the pointer. The feedback tab is action red with white text and no shadow. The player does not create it, so a project adds an element with id="feedback_button" holding an icon and a link. A glossary term is marked with a dotted underline as well as its colour, and its definition (.glossaryTip) is ink with white text.

Component Usage Guidelines

Buttons
  • Primary: Main action, one per section
  • Secondary (.button-secondary-outline): alternative actions, cancel
  • Success: Confirmations, saves
  • Filled black (.button-secondary): existing content only
Accessibility
  • All components have focus states
  • Use aria-label for icon-only buttons
