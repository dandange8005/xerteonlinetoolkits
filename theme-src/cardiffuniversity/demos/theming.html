About Theming

To give a project its own colours, set two values: --color-brand-primary, the main brand colour, and --color-brand-secondary, a dark supporting colour. Every brand-coloured part of the theme follows them, and the darker and lighter shades it needs are mixed from them. Text, links, error red and the other fixed colours stay as they are.

Type, spacing and shapes come from shared roles: CSS custom properties named --cu-*, generated from the Cardiff Resource Design System. Override those once, at :root, in CSS that loads after the theme, and everything that uses them follows.

How the layers fit
  1. Design system tokens (scss/_cu-tokens.scss, generated): the --cu-* roles. Do not edit this file; override the roles instead.
  2. Theme names (scss/_allvariables.scss): the two brand colours, the shades mixed from them (such as --color-action), and older names such as --font-size-body pointing at the roles.
  3. Components: read the roles or the aliases, so an override at :root reaches both.

Where Overrides Go

In the Xerte editor, open the project's optional properties and add either:

  • Styles: paste the CSS directly. It applies to that project only.
  • Stylesheet: upload a .css file, to share the same overrides across several projects.

The player loads both after the theme, so their :root declarations win.

Example: a green and navy brand
Two values restyle every brand-coloured part. Contrast checked: white on the button (the green mixed 85% with black) is 6.24:1, white on the navy navbar is 15.97:1, and the green edge on white is 4.81:1.
:root {
    /* edges, markers, primary buttons */
    --color-brand-primary: #00843D;
    /* navbar, footer, secondary buttons */
    --color-brand-secondary: #14213D;
}
Example: larger reading copy and rounder controls
:root {
    --cu-text-body: 21px; /* reading copy */
    --cu-radius: 8px;     /* controls; panels stay square */
}

Roles You Can Override

To changeOverride at :root
Main brand colour: header edge, current-page markers, side-menu selection, primary buttons, feedback tab--color-brand-primary
Dark supporting colour: navbar, footer, secondary buttons, .bg-dark, tabs and pills, progress bars, back-to-top button, Do/Don't labels--color-brand-secondary
Primary button and its hover, only if the mixed shades fail contrast--color-action, --color-action-hover
Reading copy size and font--cu-text-body, --cu-body
Display, section and component headings--cu-text-display, --cu-text-section, --cu-text-component
A spacing step--cu-space-4 and the other steps
Control corners--cu-radius (structural panels stay square)
Overlay shadow--cu-shadow-lg and the other tiers
Fast motion--cu-fast, --cu-ease
Xerte focus-ring geometry--focus-ring-width, --focus-ring-offset

Older names such as --font-size-body still work for the components that read them, but override the --cu-* role when a change should reach old and new components alike. --cu-red still restyles the brand primary, but --color-brand-primary is the supported name.

What Theming Does Not Change

  • Logos and identity assets. The Cardiff logo is an image; replace it in the project's header settings.
  • Text and in-page controls. Body text and headings are always ink, whatever the secondary colour. Links, focus rings, fields, the skip link and the glossary tip do not follow the brand either. Tabs, pills, progress bars, the back-to-top button and Do/Don't labels do: they take the secondary colour.
  • Error, Warning and chart colours. Error red, the required-field asterisk, the Warning callout and the first chart series read the design system's palette directly, so changing the brand colours leaves them Cardiff red. They are separate decisions: override --cu-error, --cu-callout-warning or --cu-chart-single deliberately if a brand needs it, and check each one's contrast.
  • Part of a page. Overrides belong on :root. Setting a role on one section does not restyle it reliably, because the older names were resolved at :root.
  • Page variants. For an optional variant, as on this page, put the overrides under :root[data-theme="your-name"] and set that attribute on <html>. The theme ships no built-in variants.
  • Another institution's theme. Fork the theme with its own token source and review the whole palette. Changing the two brand colours alone is not a rebrand.

Check contrast for every colour you change: 4.5:1 for text, 3:1 for control boundaries and markers.

  • White text on the primary mixed 85% with black (the primary button). A light primary such as a yellow will not reach 4.5:1; set --color-action and --color-action-hover yourself.
  • White text on the secondary and on the secondary with 14% white (the navbar's current page), and grey footer text on the secondary. Choose a dark secondary.
  • Pill text in the secondary on white, 4.5:1; the tab underline and progress bar against white and the grey track, 3:1.
  • The primary edge against white, 3:1 or better.

Dark mode is not a tested feature of this theme.
