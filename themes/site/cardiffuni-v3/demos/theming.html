About Theming

The theme's colours, type, spacing and shapes come from shared roles: CSS custom properties named --cu-*, generated from the Cardiff Resource Design System. Every component reads those roles, directly or through the theme's older names. To restyle a project, override the roles you need once, at :root, in CSS that loads after the theme. Everything that uses a role follows it.

How the layers fit
  1. Design system tokens (scss/_cu-tokens.scss, generated): the --cu-* roles. Do not edit this file; override the roles instead.
  2. Theme aliases (scss/_allvariables.scss): older names such as --font-size-body and --color-action, pointing at the roles.
  3. Components: read the roles or the aliases, so an override at :root reaches both.

Where Overrides Go

In the Xerte editor, open the project's optional properties and add either:

  • Styles: paste the CSS directly. It applies to that project only.
  • Stylesheet: upload a .css file, to share the same overrides across several projects.

The player loads both after the theme, so their :root declarations win.

Example: a blue brand
Brand marks and the primary action, with contrast checked: white on #1A5A8F is 7.23:1.
:root {
    --cu-red: #1F6FB2;          /* brand marks: header edge, current-page markers */
    --cu-action: #1A5A8F;       /* primary button and feedback tab */
    --cu-action-hover: #134570; /* their hover */
}
Example: larger reading copy and rounder controls
:root {
    --cu-text-body: 21px; /* reading copy, and --font-size-body with it */
    --cu-radius: 8px;     /* buttons, fields and other controls; panels stay square */
}

Roles You Can Override

To changeOverride at :root
Brand marks (header edge, current-page markers)--cu-red
Primary action and its hover--cu-action, --cu-action-hover
Reading copy size and font--cu-text-body, --cu-body
Display, section and component headings--cu-text-display, --cu-text-section, --cu-text-component
A spacing step--cu-space-4 and the other steps
Control corners--cu-radius (structural panels stay square)
Overlay shadow--cu-shadow-lg and the other tiers
Fast motion--cu-fast, --cu-ease
Xerte focus-ring geometry--focus-ring-width, --focus-ring-offset

Older names such as --font-size-body still work for the components that read them, but override the --cu-* role when a change should reach old and new components alike.

What Theming Does Not Change

  • Logos and identity assets. The Cardiff logo is an image; replace it in the project's header settings.
  • Error, Warning and chart colours. Error red, the Warning callout and the first chart series read the design system's palette directly, so changing --cu-red leaves them Cardiff red. They are separate decisions: override --cu-error, --cu-callout-warning or --cu-chart-single deliberately if a brand needs it, and check each one's contrast.
  • Part of a page. Overrides belong on :root. Setting a role on one section does not restyle it reliably, because the older names were resolved at :root.
  • Page variants. For an optional variant, as on this page, put the overrides under :root[data-theme="your-name"] and set that attribute on <html>. The theme ships no built-in variants.
  • Another institution's theme. Fork the theme with its own token source and review the whole palette. Changing --cu-red alone is not a rebrand.

Alternate brands and dark mode are not tested features of this theme. Check contrast for every colour you change: 4.5:1 for text, 3:1 for control boundaries.
